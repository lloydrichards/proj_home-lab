# Service register

Live addresses, deployed versions, access policies, and recovery details are kept in ignored `local/configuration/devices/_reference/services.md`. This public register describes service roles. See the [documentation privacy policy](../../docs/how-to/keep-local-configuration-private.md) before adding operational details.

## Services

home-lab provides private development and backups. remote-lab hosts applications. admin-lab provides Pi-hole DNS. Device READMEs link their operating guides.

## Pi-hole network configuration

The router supplies Pi-hole through IPv4 DHCP. IPv6 DNS can bypass filtering and remains outside the accepted setup scope. Follow [Set up Pi-hole](../admin-lab/how-to/set-up-pihole.md) and [Check DNS](../admin-lab/how-to/check-dns.md).

The [Tailscale policy example](tailscale-policy.json) illustrates DNS access from one client. It omits the deployed device map and management grants. Obtain the live policy from the private record before administration.

## Private SSH access

Use [Connect with SSH](../../docs/how-to/connect-with-ssh.md). Obtain actual host addresses and trusted fingerprints from the private record.
